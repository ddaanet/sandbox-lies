- Make `just precommit` cheaper past `bats -j` and the parallel shellcheck (59 s down to about 20 s, load 4 to 6 on 4 cores, 2026-11-06). The `_verdict_path_read` timing case no longer leads: its correctness checks ran under bats' DEBUG trap, and without it the case takes about 2.5 CPU s where it took 22 (2026-11-13). Any other case that runs a long shell loop in a subshell of the test body pays the same trap cost; none has been looked for.
- A checkout whose only refusal is git's `warning:` unlink of a file the target deleted (exit 0, HEAD moved, file left untracked) gives no `partial=1`, so the `readonly-path` verdict prints the bare re-run act and no recovery clause. Cause recorded in `docs/references/readonly-path.md`; a fix adds that message to the partial-checkout needles. It waits for a recorded case: a search of the whole corpus on 2026-11-13 found no exit-0 checkout whose only refusal is that warning with the read-only-filesystem message, only lab reproductions, which the cutter cannot use. The one exit-0 checkout with unlink warnings (`git checkout unification`, 2026-01-22) carries `error:` refusals too and ends in `Operation not permitted`, the item below.
- A checkout refused with `Operation not permitted` gets no `readonly-path` verdict: the matcher takes only the read-only-filesystem and busy-device messages (`lib/matchers.sh` ~147). Recorded case: `git checkout unification`, `-Users-david-code-edify`, 2026-01-22, exit 0 with HEAD moved. The corpus check is done (2026-11-13, untracked `.claude/backlog-eperm-corpus.md` and `.claude/backlog-eperm-replay.md`): five line-anchored git shapes match 28 real refusals in 70,457 Bash results, all sandboxed and all sandbox-caused, plus 4 results that only quote the message; no refusal ran with the sandbox off, and all are macOS. Whether the matcher takes the five shapes is my human partner's decision, asked on 2026-11-13 and not yet answered.
- The `phantom-gitadd` verdict (`lib/verdicts.sh`, `manual/detectors.md`) says to re-run unsandboxed with no wait, while `phantom-chardev` and the lock `mask` verdict carry a qualifier about no sandboxed command running alongside. A probe on 2026-11-06 (CC 2.1.318, Linux) could not reproduce the refusal: masks now land as zero-byte read-only regular files, not character devices, and `git add` stages those without complaint; masks also land only in the directory a sandboxed call starts in, so a subagent cannot put them in a scratch repo. The probe needs the main session (its cwd persists) and a sandbox that still lays character-device masks; compare an immediate re-run with one while a backgrounded sandboxed command is alive, since the siblings' qualifier is about a concurrent command.
