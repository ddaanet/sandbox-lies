## Remaining

- Make `just precommit` cheaper past `bats -j`, which `just test` now uses. `bats --timing`'s largest remaining costs: shellcheck (40 to 58 s) and the `_verdict_path_read` timing case (19 s, untraced; the timings it prints are under 0.4 s). Per-file `xargs -P` shellcheck takes 8 to 10 s but is no drop-in: given files one at a time it loses cross-file sourcing, and reports SC1091, SC2034 and SC2154 on a tree the whole-list run passes, some in vendored `plugin-dev/release.sh`.
- Shipped comments in `lib/` and `hooks/` (`lib/verdicts.sh`, `lib/verdicts-locks.sh`, `lib/probes.sh`, `lib/probes-readonly.sh`, `lib/matchers.sh`, `hooks/check-jq.sh`) cite `docs/design.md` and `docs/references/`, which `dist.include` does not ship. Same defect as the `plans/` citations fixed in the recovery batch: point them at a shipped doc, or say "in the plugin repository" as `refused-merge-recovery.md` does.
- A checkout whose only refusal is git's `warning:` unlink of a file the target deleted (exit 0, HEAD moved, file left untracked) gives no `partial=1`, so the `readonly-path` verdict prints the bare re-run act and no recovery clause. Cause recorded in `docs/references/readonly-path.md`; a fix adds that message to the partial-checkout needles, with a fixture cut from `git checkout markdown`-style corpus hits.
- A checkout refused with `Operation not permitted` gets no `readonly-path` verdict: the matcher takes only the read-only-filesystem and busy-device messages (`lib/matchers.sh` ~147). Recorded case: `git checkout unification`, `-Users-david-code-edify`, 2026-01-22, exit 0 with HEAD moved. Whether this message should fire needs its own corpus check, since it has other causes than the sandbox; the README already marks the macOS sandbox's own messages unverified.
- The `phantom-gitadd` verdict (`lib/verdicts.sh`, `manual/detectors.md`) says to re-run unsandboxed with no wait, under either flag, while `phantom-chardev` and the lock `mask` verdict carry the no-sandboxed-command qualifier for the same mechanism. An abort on the unsandboxed re-run is inferred from `manual/detectors.md`, not probed: probe it first, then word the re-run as they do. `docs/references/verdict-wording.md` quotes the phrase as its example of an imperative act.
- `tests/verdicts-readonly-path.bats`' `_verdict_path_read` timing case still uses wall seconds (`perf_counter`, about line 231). `tests/probes-readonly-tokenize-time.bats` moved to CPU seconds after load turned it red twice on 2026-11-05; this case has not been seen failing, so check whether it can before changing it.
- `tests/probes-readonly-tokenize-time.bats` still runs its cases one at a time (`BATS_NO_PARALLELIZE_WITHIN_FILE`) so a dense case is not timed against a plain word that ran without it. A review's probes on 2026-11-05 found CPU ratios barely move under one-sided load, so the setting may no longer earn its serial cost. Running the cases in parallel is untried.
- A code commit got slower: `gate-code` took 195 s where the pre-split gate took 173 s, both forced on the same machine on 2026-11-05 with 5 to 8 load. `tests/gate-coverage.bats` now builds its scratch tree once and copies it per case, which took it from 70 to 80 s to 58 to 64 s under `bats -j 8` at load 9 to 17; `tests/task-files-cache.bats` still builds it per case, in five of its six cases, about 1 min serial. A prose commit dropped to about 49 s.
