## Remaining

- The `readonly-path` verdict misleads after a checkout that moved HEAD (exit 0 after only an unlink failure). For a named-branch `git checkout <branch>`, `target=` resolves to the branch now checked out, no file matches it, and the verdict prints no merge clause (`lib/verdicts.sh` ~315-322, `manual/detectors.md` ~173-181), only the bare re-run act: that re-run does nothing ("Already on") and adds a reflog entry the recovery script has to skip. The clause's false "with HEAD unmoved" shows only when no target resolves and the text carries `partial=1`, e.g. `git checkout -`. Separately, the `update-config` act a `.claude/settings.json` path draws is the wrong act when the write was a checkout or merge. Both are detector changes needing a fixture cut by `tests/extract-fixtures.py`, and touch `docs/design.md` (at its 400-line cap, so a split comes first) and `manual/`. Evidence: `plans/2026-10-31-brief-sandboxed-checkout-moves-head.md` and `skills/sandbox-lies/references/refused-merge-recovery.md`. The split also records `bin/sandbox-lies-recover` (the recovery script) in the design.
- `tests/docs.bats` lists only the index (`git ls-files -s`) while the precommit sentinel hashes files on disk, tracked or not: a file under `inbox/` or `plans/` that is untracked when precommit records its pass can be `git add`ed and committed without the sweep ever reading it (`plugin-dev/manual/gates.md`, the hash section). The fix belongs in docs.bats, listing `-co --exclude-standard`; that also lists the sandbox's untracked masks (char devices, zero-byte dotfiles), so it must skip non-regular and empty files rather than fail on them. `scripts/check-line-limits.sh` has the same gap through `scripts/lib/tracked.sh`: `tests/recover.bats` passed precommit at 554 lines while untracked, and the cap fired only once it was committed.
- `skills/sandbox-lies/SKILL.md` is 10316 bytes, over the 10000-byte hub cap, and no gate measures bytes (`precommit` wires `check-refs` only; `scripts/check-line-limits.sh` caps a SKILL.md by lines). Split at a seam rather than trimming: the probe narrative and per-version `$TMPDIR` values near the top are evidence that fits `references/excluded-commands.md` and `references/masks-and-gates.md`. Wiring `check-size` is a separate proposal.
- Shipped comments point at files that do not ship: `bin/sandbox-lies-recover` (header) and `lib/matchers.sh` (line 11) cite `plans/`. Point them at a shipped doc instead.
- `bin/sandbox-lies-recover` has `#!/bin/bash`, which fails where no `/bin/bash` exists (NixOS); the hooks use `#!/usr/bin/env bash`.
- `bin/sandbox-lies-recover` passes each path to `git checkout HEAD --` as a pathspec. A path opening with `:` is parsed as pathspec magic: a tracked file named `:!x` reads as "everything except `x`" and would restore every file, `keep` work included. Run the script's pathspec-taking git calls with `--literal-pathspecs`, pinned by a case with such a name.
- The `readonly-path` verdict's merge/checkout clause (`lib/verdicts.sh` ~315-322, `manual/detectors.md` ~178) tells the agent to restore files from HEAD by hand and re-run, while the skill runs `sandbox-lies-recover`; an agent acts on the verdict in front of it and may restore by hand, missing the plan's `keep` set and the untracked files the target added. The verdict should name the script; this belongs with the first `readonly-path` item above (detector change, `manual/` update).
- The `git-lock` verdict called a lock a sandbox artefact and prescribed an unsandboxed re-run, on a call that was already unsandboxed: `just release minor`, which `excludedCommands` covers and which passed the toolkit's sandbox-refusing preflight, died on `git add` with the lock present, and the lock was gone a moment later. A lock absent when probed is also what a short-lived real holder leaves, so that outcome should not assert the sandbox as the cause. Detector change: fixture, `manual/detectors.md`.
