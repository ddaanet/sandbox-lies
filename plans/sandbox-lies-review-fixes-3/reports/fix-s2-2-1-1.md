# Fix s2 2.1/1 — walk starts at the cwd of a nested tree

Finding 26 (Minor, coverage) of `reports/deliverable-review.md`: the mutant that
walks the partial-checkout top from the cwd's parent survived the resolve
suite. This slice adds one case.

## Change

`tests/probes-readonly-resolve.bats` gains one case, placed after the
linked-worktree case and before the BSD case:

`partial-checkout path joins onto a linked worktree's top when the cwd is that top`

The tree: a main checkout at `$BATS_TEST_TMPDIR/main` with a linked worktree
at `main/wt`, both holding `d/f`. The probe runs with cwd = `main/wt`, the
worktree's own top, and a partial-checkout refusal naming `d/f`.

Expected: `path=<tmp>/main/wt/d/f`, outcome `writable`, empty stderr, exit 0.

## What fails it, and what else could produce the same output

- A walk that starts above the cwd meets the main checkout's `.git` first and
  prints `main/d/f`. The path assertion fails. This is the 2.1/1 mutant.
- A walk that ignores `.git` entries and joins onto the cwd prints
  `main/wt/d/f`, which is the same path as the expected one. That is not a
  survivor for 2.1/1: the existing "no .git above the cwd" and "linked
  worktree's top from a subdirectory" cases already cover the cwd-join and the
  two-level walk, and this case does not need to tell them apart.
- A wrong outcome from a path that was right would show up on the
  `writable` line; both `d/f` files are writable, so the path assertion is the
  one that carries the discrimination.

The case uses the cwd as the top itself, so it cannot be satisfied by the
two-level walk the neighbouring case already pins.

## Mutation proof

Mutant (one occurrence in `lib/probes-readonly.sh`, the walk call in
`probe_readonly_path`): walk from the cwd's parent.

- Replacement, old to new:
  `base=$(_readonly_git_dir "$cwd") || base="$cwd"`
  becomes
  `base=$(_readonly_git_dir "${cwd%/*}") || base="$cwd"`
- Landed: `command grep -n 'cwd%/\*}") || base' lib/probes-readonly.sh` prints
  line 57.
- Red on the case's own assertion:
  `not ok 4 partial-checkout path joins onto a linked worktree's top when the cwd is that top`,
  failing on `[ "$(path_line)" = "path=$wt/d/f" ]` (tests/probes-readonly-resolve.bats
  line 107). The run reported 9 passed, 1 failed.
- Restored by the reverse replacement (strings swapped, no backup, no git
  checkout). Proof: `command grep -c 'cwd%/\*}") || base'` prints `0`;
  `git diff --stat -- lib/probes-readonly.sh` is empty; the suite is green at
  10 passed, 0 failed.

Green on the unchanged code: `scripts/run-bats.sh tests/probes-readonly-resolve.bats`
gave 10 passed, 0 failed before the mutation.
