# Review: `_verdict_path_read` per-escape decoder (second pass)

**Scope**: uncommitted diff of `lib/verdicts.sh` and
`tests/verdicts-readonly-path.bats`. **Mode**: review + fix.

## Verdict

The decoder was correct for every `printf %q` output. Two defects sat in the
escapes the grammar admits but `%q` never writes. Both are fixed, with a test.
Assessment: Ready.

## Correctness checks

- **Round trip.** 1540 generated paths on the system bash (5.2.37) and on
  3.2.0. Every control byte 1-31 and 127, plus 128, 195 and 255, was crossed
  with digits 0-9 and `a`. Four shapes per pair:
  - the byte then a digit, in a path;
  - the byte-digit pair twice;
  - a `'`, a backslash and a space beside the byte;
  - a literal `\0046` beside the byte.

  Wires were generated by 5.2 and by 3.2.0, and the two files were identical.
  All four generator and decoder pairings decoded byte-exact (compared as hex,
  so NUL, newline and trailing-newline cases are covered): 0 failures.
- **Trailing backslash, loop exit.** `$'a\'` (backslash then quote, no closing
  quote) fails the grammar, rc 1. Each iteration consumes at least one
  character, so the loop terminates.
- **`\NNN` read as `\0NNN`.** `\1234` decodes to `S4` on both bashes: exactly
  three digits, and the next digit stays literal.
- **`\E`, `\a \b \f \n \r \t \v`, `\\`, `\'`** all decode correctly on 5.2
  and 3.2.
- **No `%b` over wire text as a format.** `%b` always receives the escape as an
  argument. No eval.

## Defects found and fixed

1. **`\"` kept its backslash.** `%b` leaves `\"` as two characters, while
   `$'\"'` is `"`. The outline's escape list includes it.
   - Fix: `\"` is stripped like `\'`.
2. **Unknown escapes reached `%b`.** The grammar admits any `\.`. For `\x`
   (not followed by hex digits), `printf` printed a `missing hex digit`
   complaint to stderr. `\cX` was read differently on 5.2 and 3.2: 5.2 gave
   `X`, 3.2 gave `\001X`. A short `\12` decoded to a control byte plus `2`.
   - Fix: a `case` accepts only `\' \" \\ \a \b \E \e \f \n \r \t \v`. Any other
     escape clears `_verdict_path_raw` and returns 1, which reads as no path.
   - The clearing matters: the config-lock mask arm (`lib/verdicts.sh:82`)
     reads `_verdict_path_raw` without checking the return status. A partly
     decoded prefix would otherwise still match the `.claude/settings.json.lock`
     suffix.

M1 is equivalent. Bash's `%b` reads `\NNN` the same as `\0NNN` when the
argument is the single escape, and the loop always passes a single escape.
The `0` is harmless belt and braces. What the digit-after-escape test guards
is the isolation (one escape per `%b` call), and M3 and M2 break exactly that.

## Survivors handled

New test `_verdict_path_read decodes \" and reads an escape %q never writes
as no path, silently` in `tests/verdicts-readonly-path.bats`. A
reviewer-written second-pass test.

- It asserts `$'/x/a\"b'` decodes to `/x/a"b`.
- For four forged wires (`\x41`, `\cA`, `\12`, `\q` after a decoded prefix) it
  asserts exactly `rc=1 raw= shown=` with stderr merged in.
- State of the world that fails it:
  - a `\"` that keeps its backslash;
  - an unknown escape decoded or passed to `%b`;
  - a prefix left in `_verdict_path_raw`;
  - any stderr output.
- Red under M7, M10, M12 and M13 (one failure each). Green after each restore
  (readonly-path: 13 passed).
